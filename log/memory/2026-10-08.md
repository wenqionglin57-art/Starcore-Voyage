## 详细记录

### 先把「成功」的定义从一元的改成多元的

原 `planRoute` 用 `minHp = s.hp` 做剪枝，也就是**只认无伤路线**。这条约束是隐形的天花板：

- 想让关卡更难 → 加激光 → 一旦无伤解不存在，提示 / 演示**直接失效**（玩家看到的是「算不出来」而不是「这关很难」）；
- 一旦无伤解存在，`par` 又必须 ≥ 路线长度，于是难度只能体现在「步数多」，不体现在「决策险」。

改动很小，影响很大：

- `planRoute(s, cap=20000, damageBudget=0)`：把原来的 `minHp` 换成 `floor = max(1, s.hp - damageBudget)`。`budget=0` 时与旧行为**逐位一致**（回归测试用「临时把第 1 关换成 3 格连续激光」验证：`budget=0` 返回 `null`，`budget=1` 给出 10 步路线）。
- `planRouteAdaptive(s)`：按 `[0,1,2]` 逐级降档，返回 `{path, budget}`；提示与演示都改走它。无伤解不存在时不再失效，而是明确告知「这条路线需要承受 N 格伤害」。
- `LEVELS` 新增 `budget` 字段（仅第 21、24 关为 1，其余 0）。

**别把两个「伤害上限」混了**：`takeDamage(...,guard,...)` 里的 `guard{used:false}` 是**单回合最多掉 1 格护盾**（第七轮 P1）；`damageBudget` 是**整条路线允许掉几格**。前者防「一回合被叠死」，后者决定「哪种路线算成功」。

### 四项新机制：全部纯函数、全部进 `step`

- **相位器 `%`**：拾取得 1 点充能；按 `Q`（或点「调相」按钮）耗 1 步、`phase=(phase+1)%2`，翻转**全局**激光相位。`laserActive(moves,phase)` 与 `onActiveLaser(s,x,y)` 都加了相位参数。常常比「原地等两步」更划算，所以它是「用一步换两步」的资源，而不是装饰。
- **可推箱 `X` + 压力板 `+` + 闸门 `D`**：`gateOpen(st)` 是**纯函数**（压力板被玩家或箱子压住即开），因此不进 `planKey`；`crates` 进 `planKey`。推箱时若箱后格可通行，箱子与玩家一起前进；否则 `blocked` 且**不计步**。箱子顺带能挡住暗影兽——同一个物体在两条规则里都有用。
- **传送门 `O`**：按出现顺序两两配对（`portalPairsByLevel`），踩入即传送到配对门，**不额外耗步**。在 `buildDistTable` 里被建成 0 代价边（0-1 BFS，`queue.splice(head,0,...)`），保证距离仍是真实步数的下界、启发式可采纳。
- **巡逻哨兵 `P`**：位置是 `moves` 的**纯函数**（`patrolAt(level,moves)`，取所在行最大连续可行走段来回折返），因此不进 `planKey`、零搜索成本；但会造成伤害，所以 `planKey` 里只加一个 `moves%patrolCycle`。这正是方案说的「外生型」——威胁是真的，搜索成本是零。

### 踩坑

- **CRLF**：`outputs/index.html` 是 CRLF，补丁脚本必须先 `raw.replace(/\r\n/g,'\n')` 处理、再按原样写回；否则锚点命中 0 次。本轮 `_patch_v8.cjs` 首次就栽在这里，报 `[新增样式] 锚点命中 0 次`。
- **第 21–24 关的测试里 `loadLevel` 静默失败**：更早的用例已经 `loadLevel(0)` 清掉存档，第 21 关未解锁，`loadLevel(20)` 直接 `return`，于是「拾取相位器」用例拿到 `gotCharges:0` 而不是 1。修法：把解锁播种（`store.records[0..22]` 补齐 + `save()` + `renderTabs()` + 断言 `unlocked()===23`）提到该用例最前面。**`loadLevel` 对未解锁关静默返回，是老坑，会反复咬人。**
- **推箱测试的「推离压力板」用例是无效的**：玩家自己站在压力板上时 `gateOpen` 仍为 true（板被玩家压着）。改成两条真用例——「玩家自己站板也开门」与「真实推箱把箱子推上压力板」。
- **L21 的相位器一度只是装饰**：`_probe.cjs` 显示最优解 `phaseSteps=0`，即相位器根本没被用上。写 `_probe2.cjs` 批量试算 11 种候选结构，才找到「最优 42 步且真的调相 1 次」的布局（走廊 `#S.%^.^....E#` + 下半区对称星核）。**结论：新机制必须由 `optimal-levels` 证明「最优解真的用到」，否则就是摆设。**
- 同一条消息里并发多个 `Edit` 打同一个文件会**静默丢改动**（第六轮踩过）。这轮所有对 `index.html` / `README.md` 的多点改动都改走**带唯一锚点断言的补丁脚本**，未再复现。
