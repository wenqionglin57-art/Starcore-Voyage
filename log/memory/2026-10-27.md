## 详细记录

### 为什么是「每日挑战」

前八轮把「关卡质量」做透了：24 关、求解器标定、四项机制、18 项成就。但它仍然是一个**一次性**的单机游戏——通关即结束。真正让一个小游戏变成日常的，是三个条件同时成立：

1. **一天只有一次机会**（稀缺，值得认真对待）；
2. **所有人面对同一道题**（可比，才有讨论）；
3. **结果可以炫耀但不剧透**（可传播）。

这三条正好都能在没有服务器、没有账号的前提下做到：题目由**日期**唯一决定，结果是一段纯文本。

### 生成：让求解器当裁判，而不是靠手感

```
日期字符串 → FNV-1a 哈希 → mulberry32 伪随机
  → 递归回溯挖迷宫（只在奇数格之间挖，天然全连通）
  → 随机敲掉 2–5 堵墙制造环路（纯树状迷宫没有「选哪条」的余地）
  → 从起点 BFS：最远点放出口，次远点放星核（彼此曼哈顿距离 ≥ 4）
  → planRoute(state, 80000, 0) 验收
  → 最优步数落在 20–52 才算合格；par = round(最优 × 1.2)
```

两个关键取舍：

- **必须固定尝试次数（80），不能设「跑满 N 毫秒」的时间预算。** 否则快机器与慢机器会在不同的候选上停下，同一天不同设备拿到不同的图——这直接摧毁「所有人同一张图」的前提。
- **验收标准必须包含步数区间。** 只验「可解」不够：太短会像热身，太长会让每日变成负担。实测两天分别是 38 步（par 46）与 42 步（par 50），第 0 次尝试即通过。

生成器的种子只由日期决定，所以同一日期永远得到同一张图；`genDaily` 的 80 次尝试也是确定性的。

### 隔离：每日成绩绝不能进战役纪录

这是最容易出错、也最容易被玩家发现的地方。凡是 `store.records[state.level]` 出现的位置，都要么分支、要么确认不会被每日走到：

- `finish()`：`isDaily()` 时走 `recordDaily()`，不写 `records`。
- `pushUndo()` / `undoMove()`：每日不备份、不恢复 `records`（否则会把 24 号槽写进战役纪录）。
- `updateUI()` 的「本关最佳」：每日读 `store.daily.best`，文案改成「今日最佳」。
- `OPTIMAL_STEPS[state.level]`：每日没有这一项，`speedrun` 统计直接跳过。
- 本局表现统计（`flawless` / `lastStand` / `monsterPerfect`）：每日整体跳过。

测试用 `JSON.stringify(store.records)` 前后完全一致 + `flawless` 增量为 0 把这条钉住。

### 窄屏的坑：折叠规则会把关卡墙折成空白

`applyTabCollapse()` 的折叠逻辑是「只显示 `.current` 那一关」。每日挑战没有对应的战役关，于是 24 个标签全被 `display:none`，只剩一条 **24px 高的空墙**——这是截图脚本里 `progress-mobile.png 382×24`（正常应为 ~106px）暴露出来的。

修法不是给它硬塞一个 `.current`（会误导），而是在每日模式下**换一个明确的入口**：

```js
const daily=isDaily();
if(back)back.hidden=!daily;
wall.hidden=daily;
if(daily){toggle.hidden=true;return;}
```

HTML 里新增 `#dailyBack`「返回星区列表」按钮，每日模式下替代关卡墙；返回战役后两者自动复位。测试断言 `wallHidden` / `backVisible` 双向切换。

### 战绩卡：三行，且不含任何地图字符

```
星核迷航 · 每日挑战 2026-10-27
★★★ 38 步（目标 46，提前 8 步）
连续 1 天
```

刻意去掉了「护盾」行：每日没有危险，护盾必然是 3/3，这一行零信息。测试直接断言分享文本**不含 `#` `*` `S` `E`**，防止把地图字符漏出去。

复制走 `navigator.clipboard.writeText`，失败则回退到隐藏 textarea + `execCommand('copy')`——`file://` 下剪贴板 API 常被拒绝，没有回退会静默失败。

### 踩坑

- **补丁脚本里用裸 `html.replace` 是危险的**：这轮第一版把锚点写成 `getElementById('game')`，实际是 `getElementById(id)`，`String.replace` 静默不生效，`DAILY_SLOT` 根本没插入，页面直接 `ReferenceError`。**所有替换都必须走带唯一性断言的 `rep()`**，定位探针也不例外。
- 忘了写 `levelOf()` 本身：`buildDistTable` 先炸。所有按关索引的代码（`step` / `stepMonsters` / `onActiveLaser` / `renderStatic` / `draw` / `buildDistTable` / `planKey`）都必须经过它。
- `planKey` 里 `patrolCyclesByLevel[24]` 是 `undefined`，`undefined > 1` 恰好为 `false`，所以没炸；但仍补了 `||1` 让意图显式。
- `trapsByLevel[24]` 是 `undefined`，`draw()` 会直接崩——补 `||[]`。
- Node 版本目录从 `22.22.2-3` 变成了 `22.22.2-6`，旧路径已不存在。

# 第十轮：冰面滑行 `~` + 冻结激光 `≈`（第 25/26 关）

## 为什么是「运动规则」而不是「又一个机关」

前九轮的机制都是往地图上**加东西**：相位器、箱子、压力板、闸门、传送门、哨兵。再堆一个同类物，玩家只会觉得地图更挤。这一轮换了个方向——不改地图内容，改**移动本身的规则**：

- `~` 冰面：踏上去就沿同一方向一直滑，直到撞上障碍或离开冰面。**整段只算 1 步**。
- `≈` 冻结激光：本质是「裹在冰里的激光」。滑过去安全，**停在那格**才按激光节奏结算伤害。

前者把「走一步」变成「滑一段」，后者把「滑到哪停下」变成一次真正的决策。两个机制叠在一起，第 26 关的第一个动作就是一道题：起点只有向下一条路，而下方第一格冰面滑下去正好停在 `(1,3)` 的冻结激光上——开局激光是**开启**的，直接按「下」会掉一格护盾。求解器给出的最优解是**先原地等 1 步**，等激光翻到关闭的窗口再下滑（第 2 步落地）。

## 状态空间：一个字段都没加

滑行是地图的确定性函数，不需要进 `planKey`。`step()` 里只多了一个循环：

```js
if(moving&&isIce(land)){
 let slid=1;
 while(true){
  const sx=ns.x+delta[0],sy=ns.y+delta[1],st=level.map[sy]?.[sx];
  if(!st||st==='#'||st==='X'||st==='O'||(st==='D'&&!gateOpen(ns)))break;
  ns.x=sx;ns.y=sy;land=st;slid++;
  const got=collectAt(ns,events);if(got.boots)pickedBoots=true;
  if(!slideThrough(st))break;
 }
 if(slid>1)events.push({type:'slide',tiles:slid,x:ns.x,y:ns.y});
}
```

真正需要小心的是**启发式**：`slideStatic()` 要给 BFS 距离表复刻同一套滑行，但忽略星箱、闸门、守卫。忽略只可能让距离更短，所以可采纳性成立，提示在第 25/26 关给出的仍是真正最优。

## 三个被自己踩到的细节

1. **星核不能刹停滑行。** 第一版里 `if(!isIce(st))break;`——星核格不是冰面，滑过去就停在星核上。于是「整段只算 1 步，沿途的星核照收」变成了「踩到星核就刹车」，一条 9 格的冰河被切成两段，机制价值直接归零。修法：抽出 `slideThrough(t)`，冰面、星核、四种道具都算「可以穿过去」，只有墙 / 箱子 / 传送门 / 关着的闸门才停。`slideStatic` 必须同步，否则距离表会比真实更**长**，启发式就不再可采纳。
2. **`slide.tiles` 少算一格。** `slid` 从 0 起算，漏掉了「进入冰面」那一格，于是 8 格的滑行播报成「滑行 7 格」。改成 `slid=1` 起步、`if(slid>1)` 才发事件（滑 1 格本来就不该弹提示）。
3. **`≈` 必须与 `^` 一起计入激光缓存。** `trapsByLevel` 早就算上了，但测试 2b 只数了 `^`，第 26 关立刻报「地图 0 / 缓存 6」。这条断言的价值正在于此——它逼着新符号必须走同一套缓存。

## 关卡不是手搓的，是搜出来的

手画冰面地图几乎必然出两种废图：要么滑行根本用不上（冰面成了贴图），要么最优步数被压到 10 步以内。所以写了个生成器（已留在 `tests/gen-ice.cjs`，以后加冰面关直接用）：DFS 迷宫 → 凿环路（**关键**，完美迷宫只有唯一解，冰面就没有取舍）→ 随机把连续走廊段改成冰 → 放星核 → 用页面里的 `planRoute` 当裁判，只收「无伤可解 + 最优 30–40 步 + 滑行 ≥5 次 + 最长滑行 ≥6 格」的图。

第 25 关来自 seed 30（底部一条 9 格冰河），第 26 关来自 seed 140 + 手工加 `≈`。然后做了一件更重要的事：**把星核挪进冰河中央**（`(8,7)`），让「滑行途中顺手收星核」成为关卡主秀，而最优步数一格没变（34）。

第 26 关的 `≈` 摆了 6 处，只挑了两处是停点：`(1,3)`（开局必经）与 `(11,7)`（右侧竖井底部）；底部 `(4,7)(5,7)(6,7)` 三连是**滑过去**的，专门教「冻结激光不吓人」。
